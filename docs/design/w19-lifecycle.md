# W19 专利全生命周期过程图与平台缺口（发明人 × 代理人 × 审查员）

> 目标：把「从想法到递交/授权」的真实协作过程完整建模，逐阶段对照平台现状，
> 让平台成为全过程的载体而不只是「三书编辑器」。反哺轮成果（千件语料）也归进各阶段。

## 一、全过程阶段图（角色 → 产出物 → 平台面 → 缺口）

                            ② 查新检索·go/no-go·布局建议              │

                            ⑨ 受理/初审/公布/实审请求(3年死线!) ◄─── 受理通知
                            ⑩ OA答辩(一通4mo/二通2mo) ◄──────────── 审查意见

## 二、贯穿性缺口：状态机「无导引」

十档 status 已建模（intake→closed，任意跳转+history 留痕），但对用户它只是仪表盘上的一个标签——**不知道每阶段该做什么、进下一阶段的门槛是什么**。真实代理流程里每阶段有明确交付物和 go/no-go 条件。→ **批1：流程伴随面板**。

## 三、实施批

### 批1「流程」伴随面板（本批主件）
- 新 CompanionId `lifecycle`（标题「流程」，icon Workflow，归属 dashboard 单元）
- 内容：
  - 10 档阶段步进条（当前高亮、已过 ✓、点击跳态走 `setCaseStatus`——复用 StatusPicker 同一入口语义，viewer 只读）
  - 当前阶段导引卡：目标 / 该做什么（3-5 条动作清单，含相关页面深链）/ 下一阶段进入条件
  - STAGE_GUIDE 常量按反哺内容写：如撰写阶段挂「密度基准 benchmarks 中位 9322 字/实施 5769」自检口径
  - 底栏：当前案态徽标 + 「下一步」快捷动作（如 drafting→review 的「提交内审」）
- 技术：`ui.ts` CompanionId+IDS、`companionMeta`、`companionBodies` 注册、Rail 加图标（与附图/术语同族）、`?panel=lifecycle` 自动生效、⌘K 自动生效

### 批2 递交要素清单（deliver 页）
- DeliverSide 新增 FilingReadinessCard：聚合检查 申请人/发明人/案号/费减/优先权一致性/申请日 + 五书非空 + preflight 0 error → 「缺 N 项」清单，每项带「去补」深链（CaseFormDialog / 工作台 / console）
- 复用 SideCard 模式，viewer 只读

### 批3 技术交底书模板
- 机构/内置模板体系（app/domain/templates.py + 前端模板选择）已有——查内置模板清单，若无交底书，补一份：发明点/技术问题/现有技术缺陷/技术方案/有益效果/可替代方案/已公开情况 七段式 docs 骨架
