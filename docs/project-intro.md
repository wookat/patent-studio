# 知撰·AI 专利撰写与协同平台 — 项目介绍

> 面向初次接触本项目的读者。

## 一句话

知撰是一个开源、可私有部署的专利撰写工作台，帮助撰写与管理中国发明专利材料：整理技术交底与论文、撰写三书（摘要 / 权利要求书 / 说明书）、复核 AI 起草与修改建议、管理附图与案卷、导出交付文件。

## 它解决什么问题

把 AI 引入专利撰写后，真正影响交付可信度的往往不是「AI 写得不够好」，而是协作与责任归属的基础设施：

- **协作失控**：撰写人、审核人、客户与外部工具同时改一份稿子，版本靠文件名区分，合稿靠人工记忆；
- **产物无法定责**：AI 生成的段落与人工撰写混在一起进入正式文本，出问题说不清是谁写的；
- **检查后置**：术语不一致、权项引用错层、图号与附图标记对不上，往往到递交前才暴露；
- **交付难复核**：交给官方或客户的文件，与系统里的「最新稿」是不是同一份内容，难以证明。

知撰的做法是先把「人办案」的流程做正确，再让 AI 在框架内帮忙：文稿、修改与导出在同一案卷内留痕可查，检查随写随跑；AI 辅助起草与提出修改建议，默认以建议方式呈现、经人复核采纳后才进入文稿。

## 适用人群

- **专利代理师与代理机构**：以案卷为单位管理撰写进度、期限与审阅流转，AI 修改建议逐条复核裁决，最终导出交付文件；
- **企业知识产权团队**：发明人交底、撰写、审校、定稿多角色流转，台账与期限让流程可见；
- **高校与科研机构**：把论文或技术交底整理为申请初稿，再由专业人员把关修改；
- **个人发明人**：在规范的撰写与检查框架里完成三书起草，不必从零熟悉专利文体。

## 典型使用情境

以一件专利材料为例：

1. 在台账新建案卷，或导入已有的 Word 文稿；
2. 导入技术交底书、论文 PDF 等材料（支持文本提取与 OCR 辅助）；
3. 需要时让 AI 基于材料起草三书初稿，或对已有文稿提出修订、批注建议，由人复核后采纳；
4. 在三书工作台撰写与修改，可在源码、版面与 PDF 预览之间切换对照；
5. 术语一致性、权项引用、图号与附图标记等检查随写随跑，递交前用体检汇总；
6. 邀请协作者批注修订，或给客户发免登录确认链接；
7. 导出 DOCX、PDF 与 CNIPA XML 文件，人工核对后走正式递交流程。

## AI 和人的分工

- **AI 做什么**：按材料起草三书初稿、以修订 / 批注形式提出修改建议、回答案内问题、跑预设的撰写与检查场景；
- **人做什么**：材料取舍、权利要求布局、复核并采纳或拒绝 AI 建议、定稿与递交决策；
- **边界**：工作台内 AI 的修改默认以建议方式提出，经人复核采纳才进入文稿；经 MCP 接入的外部工具按其授权权限操作案卷（见 [MCP 接入](mcp.md)）。AI 可能出错，正式材料须由专业人员复核。知撰不提供法律意见，不承诺新颖性、创造性、受理或授权结果，也不替代官方申请系统。

## 开源使用与参与

- **仓库**：<https://github.com/wookat/patent-studio>，Apache-2.0 许可；
- **快速开始**：`docker compose up --build -d` 后打开 `http://localhost:8000`，即可见到两个基于已公开专利重建的演示案卷；详见根目录 [README](../README.md)；
- **AI 是可选配置**：不配模型密钥仍可编辑、检查、构建与导出；启用 AI 需自行配置模型服务并可能产生费用；私有部署不等于 AI 材料不外发——配置远端模型后相关材料会发送到对应服务商网关，请按数据政策选择服务商；
- **高级协作与集成**：多人协同、外部 Agent 接入（MCP）等能力按部署形态启用，具体见[部署指南](deploy.md)与 [MCP 接入](mcp.md)；
- **参与贡献**：见[贡献指南](../CONTRIBUTING.md)；安全问题请按[安全政策](../SECURITY.md)私下报告；
- **文档**：[使用手册](user-manual.md)（操作细节）、[系统设计](design.md)（实现约定）。

## 责任边界

- 演示案卷与语料、附图库来自已公开专利文献，仅供演示与研发测试，相关权利归原权利人所有，公开可访问不等于可任意再分发；
- 本仓库不分发受限字体、完整语料 / 图库数据包或未公开申请稿；
- 工具不能替代未公开发明信息的保密责任；导出与递交前请自行或委托执业代理人核对文稿。
