# 查新 / 先行技术检索

## 何时检索

用户要求查新、新颖性、先行技术对比、权项起草、授权风险、完整申请包时先检索。用户明确说「按所给材料写、不查新」可跳过，但新颖性表述标「待检索」。

## 检索源

- CN 侧：CNIPA 公布公告系统 / 国家知识产权局公开库（可及范围内）
- 稳定页：Google Patents（CN 公开号、机器可读摘要好用）
- 学术：Google Scholar / Crossref / arXiv / PubMed / 领域库
- 用户提供文献：逐条打开核实书目录与关联性

绝不编造专利号、申请人、标题、日期、摘要或 URL；打不开/核不了的标「待复核」，不作决定性先行技术。

## 检索式构造

从发明提取 2–8 个高信噪检索单元：专业术语、名词短语、方法/动作短语、关键部件、「应用场景+核心机制」、已知别名。不用整句中文做唯一检索式；「系统/方法/模型/平台/优化」这类泛词须与技术上下文组合。

## 查新表字段（内部维护）

来源 / 检索式 / 公开号或引文 / 标题（已核实）/ 申请人或作者 / URL（已打开）/ 核心教导（自话概括不照抄）/ 相关度（高度/部分/背景）/ 未教导点 / 影响哪条权项哪节。

## 写进专利材料

- 交底书/说明书背景节写面向代理人的「检索说明」：公开库名 + 代表性关键词
- 每个最接近文献给核实过的 URL（模板允许时）
- 文献的技术方案/场景/局限用自己的话概括
- 结尾落在本质区别：本发明组合了什么、改变了什么、约束了什么、技术上改善了什么

## 检索不可行时（诚实降级）

平台 s8 场景已接真实检索（`backend/app/agent/prior_art.py`）：provider 由 `PATENT_STUDIO_PRIOR_ART_PROVIDERS` 逗号序决定——patsnap（PATENT_STUDIO_PATSNAP_KEY，PatSnap Open 全球库含 CN 全文）、ops（EPO OPS，OPS_KEY+SECRET）、openalex（免 key，NPL 侧）。逐条检索式出真实命中表（公开号/标题/日期/链接）作机器初筛。

无网络/库/凭据时：明确说哪些检索没完成、哪些权项或新颖性表述属待确认、需要代理人手动核实什么——产出「待检索查新笔记」（检索式+空表+待确认项），不藏限制、不伪造结论。
