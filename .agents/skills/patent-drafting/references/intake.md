# Intake 与证据扫描

## 最少打扰问项（只问改变专利策略的事实）

材料足够则带着明示假设直接干，不逐项盘问：

- 技术主题：一句话的产品 / 算法 / 装置 / 方法 / 应用场景
- 交付物：发明点挖掘 / 技术交底书 / 权项 / 说明书 / 摘要 / 修订
- 权项类型偏好：方法 / 装置·系统 / 介质·设备 / 产品 / 用途 / 不确定
- 源材料：案卷 attachments 内文件名、路径、笔记、既有草稿
- 脱敏级别：公司名 / 客户数据 / 精确参数 / 未发表结果
- 发明人问卷（Patent Studio 六字段，非空字段优先于原文）

## 证据优先级（每个关键技术事实留锚点）

| 优先级 | 来源 | 提取什么 |
|---|---|---|
| 1 | 既有交底书 / 发明报告 / 专利笔记 | 主张新颖性、已知实施例、欲保护范围 |
| 2 | 设计文档 / 论文 / 实验记录 | 问题、架构、算法/流程、实验、技术效果 |
| 3 | 核心代码 / 配置 | 实际实现、数据流、参数、阈值、状态机 |
| 4 | 产品文档 / issue / 会议纪要 | 约束、部署条件、边界情形、用户侧效果 |
| 5 | 原始图表 | 架构、流程、实验证据、参数范围 |

docx/pdf/md/txt 走 convert.extract 抽取（附图入 figs/），不要因已有纯文本而跳过 Office/PDF 源。

## 发明点提取表（产 3–5 候选，除非已指定）

- 候选题名：「一种…」
- 技术问题：现有系统/技术的具体缺陷（非商业痛点）
- 技术手段：真实结构 / 步骤序列 / 算法 / 参数关系 / 部件协同
- 技术效果：可度量或技术上可解释的效果（非商业价值）
- 证据支撑：文件 / 页 / 节 / 函数
- 权项类型：方法 / 装置 / 介质 / 产品 / 用途
- 交底缺口：需要问发明人的缺失事实
